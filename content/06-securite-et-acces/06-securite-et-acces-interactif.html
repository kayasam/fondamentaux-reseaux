NAT — Network Address Translation

NAT (Network Address Translation) est le nom général donné à la traduction d'adresses. Pour comprendre un schéma, posez une seule question : quel champ du paquet le routeur modifie-t-il ?

LAN → Internet PAT : le cas courant

Le routeur modifie la source et utilise les ports pour partager une seule IP publique.

Internet → LAN DNAT : publier un service

Le routeur modifie la destination pour rediriger un port public vers un serveur privé.

1 privée ↔ 1 publique NAT statique : mapping fixe

Une machine reçoit une IP publique dédiée. Le mapping reste identique dans le temps.

À retenir d'abord
Sur une box Internet, « faire du NAT » signifie presque toujours faire du PAT sortant : plusieurs machines privées partagent l'unique IP publique du routeur.

NAT Statique (mapping 1:1)

Le NAT statique associe une IP privée à une IP publique dédiée de façon permanente. Le mot statique décrit le mapping : il ne dit pas à lui seul si l'on fait du SNAT ou du DNAT.

Dans le sens sortant, ce mapping peut servir de SNAT statique : l'adresse source privée devient une adresse publique fixe. Dans le sens entrant, le même mapping peut servir de DNAT statique : l'adresse publique dédiée redirige vers la machine privée.

Limitation du NAT statique
Il faut autant d'adresses IP publiques que de machines. Avec 100 postes, il faudrait 100 IPs publiques ! Face à la pénurie d'IPv4, c'est rarement viable → d'où l'invention du PAT.
Cas d'usage du NAT statique
Le NAT statique est encore utilisé quand un serveur interne doit être joignable depuis Internet avec une IP publique fixe dédiée (ex. serveur web en DMZ, serveur mail). Dans ce cas, on combine souvent un mapping statique avec du DNAT entrant et du SNAT sortant.
Piège à éviter
NAT statique ne signifie pas Source NAT. Le premier décrit une correspondance fixe, le second décrit la traduction de l'adresse source. Ce sont deux axes différents.

Masquerade — le cas Linux courant

Masquerade n'est pas une nouvelle famille de NAT au même niveau que SNAT, DNAT ou PAT. C'est une manière pratique de faire du SNAT automatiquement sous Linux : le routeur utilise l'adresse IP de son interface de sortie.

# SNAT classique : l'adresse publique est écrite explicitement
iptables -t nat -A POSTROUTING -o eth0 -j SNAT --to-source 203.0.113.1

# Masquerade : Linux prend automatiquement l'adresse de eth0
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
Quand l'utiliser ?
Masquerade est pratique quand l'IP externe peut changer : box avec DHCP, PPPoE, partage de connexion, routeur Linux de lab ou VM. En pratique, il accompagne souvent un comportement de type PAT, car plusieurs machines internes partagent la même IP externe via des ports différents.

Dans le langage courant
Quand on dit "activer le NAT" sur une box, un routeur, Hyper-V ou VMware pour donner Internet à plusieurs machines, c'est généralement du PAT : toutes les machines partagent une seule IP externe via des ports différents.
Attention — SNAT ≠ NAT Statique
Piège courant : SNAT signifie Source NAT (traduction de la source), pas "NAT statique". Un PAT de sortie, un masquerade Linux ou un mapping 1:1 sortant peuvent tous être des cas de SNAT. Ce sont deux classifications différentes : SNAT/DNAT = la direction, statique/dynamique/PAT = le type de mapping.
Rappel
NAT n'est pas un mécanisme de sécurité à lui seul, même s'il masque les IPs internes. C'est le pare-feu qui filtre réellement le trafic.

Le pare-feu (Firewall)

Le pare-feu filtre le trafic réseau selon des règles basées sur :

  • l'IP source et destination
  • le port
  • le protocole (TCP, UDP, ICMP)
  • le sens du trafic (entrant / sortant)

Proxy — intermédiaire réseau

Un proxy est un serveur qui s'intercale entre les utilisateurs et Internet. Toutes les requêtes passent par lui avant d'atteindre la destination.

Reverse Proxy

Le reverse proxy se place devant les serveurs (pas les clients). Il reçoit les requêtes entrantes et les distribue aux bons backends. Cliquez sur un flux :

Cliquez sur un flux pour voir comment le reverse proxy traite la requête.

Fonctions du reverse proxy

  • Terminaison TLS — le certificat HTTPS est géré à un seul endroit, les backends reçoivent du HTTP simple
  • Load balancing — répartir la charge entre plusieurs serveurs (round-robin, least connections…)
  • Routage — diriger /api vers un backend, /app vers un autre, selon le domaine ou le chemin
  • Protection (WAF) — filtrer les requêtes malveillantes avant qu'elles atteignent les backends

DMZ — Zone démilitarisée

Une DMZ est une zone réseau intermédiaire entre Internet et le réseau interne. On y place les serveurs qui doivent être accessibles depuis l'extérieur (web, mail, reverse proxy) tout en protégeant le LAN.

VPN — Virtual Private Network

Un VPN crée un tunnel chiffré entre deux points à travers un réseau non sécurisé (Internet). Les données sont encapsulées et chiffrées : même si quelqu'un intercepte le trafic, il ne peut pas le lire.

Principe : l'encapsulation

Le VPN prend chaque paquet réseau, le chiffre, puis l'enveloppe dans un nouveau paquet. Seul le destinataire (la passerelle VPN) peut déchiffrer :

Sans VPNAvec VPN
[IP src → IP dst] [Données en clair]
→ Tout est visible pour quiconque écoute le réseau		 [IP src → IP VPN GW] [chiffré : IP src → IP dst + Données]
→ L'observateur voit uniquement du trafic chiffré vers la passerelle

Split Tunneling

Par défaut, tout le trafic passe par le tunnel VPN (full tunnel). Le split tunneling permet de choisir :

ModeTrafic entrepriseTrafic Internet (YouTube…)Avantage
Full tunnel→ via le VPN→ via le VPN aussiSécurité maximale, tout est contrôlé
Split tunnel→ via le VPN→ sort directement sur InternetMeilleures performances, moins de charge sur le VPN
Risque du split tunneling
En split tunnel, le poste est connecté simultanément au LAN entreprise et à Internet non filtré. Si le poste est compromis, l'attaquant a un accès direct au réseau interne via le VPN. C'est pourquoi certaines entreprises l'interdisent.

Chiffrement asymétrique (clé publique / privée)

Chaque personne possède une paire de clés : une clé publique (partagée avec tout le monde) et une clé privée (gardée secrète). Elles fonctionnent ensemble mais dans des sens opposés :

Symétrique vs Asymétrique
Le chiffrement symétrique (AES) est rapide mais nécessite de partager la clé secrète. Le chiffrement asymétrique (RSA) résout ce problème mais est lent. HTTPS combine les deux : l'asymétrique échange une clé de session, puis le symétrique chiffre les données. Le meilleur des deux mondes.

Principe fondamental
La sécurité réseau est une défense en profondeur : chaque couche a ses propres protections. Une seule mesure ne suffit jamais. On combine pare-feu + VPN + chiffrement + authentification + segmentation.
