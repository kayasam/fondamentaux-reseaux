05. Couche application

DHCP, DNS, HTTP/HTTPS et les protocoles applicatifs du quotidien.

Couches hautes — rappel rapide

Dans le modèle OSI, les couches 5 (Session), 6 (Présentation) et 7 (Application) sont souvent regroupées sous le terme couche Application dans le modèle TCP/IP. C'est ici que vivent les services du quotidien.

DHCP — Attribution automatique de la configuration IP

DHCP (Dynamic Host Configuration Protocol) attribue automatiquement à chaque appareil :

  • une adresse IP
  • le masque de sous-réseau
  • la passerelle par défaut
  • les serveurs DNS
  • une durée de bail (lease)

DNS — Résolution de noms

Le DNS (Domain Name System) traduit un nom de domaine en adresse IP :

www.google.com → 142.250.74.46

Hiérarchie DNS

Enregistrements DNS

Cliquez sur un type d'enregistrement :

A

Nom → IPv4

AAAA

Nom → IPv6

MX

Serveur mail

CNAME

Alias

PTR

IP → Nom
A — Associe un nom de domaine à une adresse IPv4. Ex : example.com → 93.184.216.34. C'est l'enregistrement le plus courant.
AAAA — Associe un nom à une adresse IPv6. Ex : example.com → 2606:2800::1. Même rôle que A, mais pour IPv6.
MX (Mail Exchanger) — Indique quel serveur gère les e-mails d'un domaine. Ex : les mails pour @example.com sont envoyés à mail.example.com.
CNAME (Canonical Name) — Crée un alias. Ex : www.example.com est un alias vers example.com. Utile pour pointer plusieurs noms vers le même serveur.
PTR (Pointer) — Résolution inverse : traduit une IP en nom. Ex : 93.184.216.34 → example.com. Utilisé pour la vérification anti-spam des serveurs mail.

Commandes de diagnostic DNS

nslookup google.com       # Résolution simple
dig google.com            # Résolution détaillée (Linux)
dig -x 8.8.8.8            # Résolution inverse (PTR)

HTTP — Le protocole du web

HTTP suit une logique requête / réponse :

Codes de réponse HTTP

Cliquez sur un code :

200
301
304
403
404
500
502
200 OK — La requête a réussi. Le serveur renvoie le contenu demandé (page HTML, image, API…).
301 Moved Permanently — La ressource a changé d'adresse définitivement. Le navigateur est redirigé vers la nouvelle URL.
304 Not Modified — Le contenu n'a pas changé depuis la dernière visite. Le navigateur utilise sa version en cache.
403 Forbidden — Le serveur a compris la requête mais refuse l'accès. Problème de permissions.
404 Not Found — La page demandée n'existe pas sur le serveur. URL incorrecte ou page supprimée.
500 Internal Server Error — Le serveur a rencontré une erreur interne. Bug dans l'application, config cassée.
502 Bad Gateway — Le serveur agit comme proxy et a reçu une réponse invalide du serveur en amont.

HTTPS = HTTP + TLS

TLS (Transport Layer Security) ajoute :

  • Chiffrement — les données sont illisibles en transit
  • Authentification — le serveur prouve son identité via un certificat
  • Intégrité — les données ne peuvent pas être modifiées en route
Important
Sur un réseau non fiable, HTTP en clair est lisible par quiconque intercepte le trafic. HTTPS est devenu la norme. Les navigateurs marquent les sites HTTP comme "Non sécurisé".
