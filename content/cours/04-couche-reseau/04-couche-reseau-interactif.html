CIDR — notation sans classe

CIDR (Classless Inter-Domain Routing) remplace les classes par une notation plus souple. Le /n indique combien de bits sont réservés à la partie réseau.

Pourquoi créer des sous-réseaux ?

  • Séparer des services (administration, production, invités)
  • Limiter le broadcast — un broadcast reste dans son sous-réseau
  • Organiser l'adressage de façon logique
  • Sécuriser — contrôler le trafic entre sous-réseaux via un routeur

On découpe 192.168.1.0/24 en 4 sous-réseaux en empruntant 2 bits au champ hôte → /26 :

Règle
Dans chaque sous-réseau, la première adresse est l'adresse réseau et la dernière est l'adresse de broadcast. Elles ne sont pas attribuées à un hôte. D'où : hôtes utilisables = total - 2.

ARP — Address Resolution Protocol

Une machine raisonne en adresses IP pour savoir où envoyer ses données. Mais sur le réseau local, les trames Ethernet utilisent des adresses MAC. ARP fait le lien entre les deux.

Protocole "entre deux couches"
ARP est à cheval entre la couche 2 (MAC) et la couche 3 (IP). Il permet de répondre à la question : "Quelle adresse MAC correspond à cette IP sur mon réseau local ?"

Sécurité : ARP Spoofing
ARP n'a aucune authentification. Un attaquant peut envoyer de fausses réponses ARP pour intercepter le trafic (man-in-the-middle local). Protection : Dynamic ARP Inspection sur les switches managés, segmentation VLAN.

Structure d'un paquet IP

Le protocole IP encapsule les données de la couche transport dans un paquet. Cliquez sur un champ :

Version 4 bits
IP Source 32 bits
IP Destination 32 bits
TTL 8 bits
Protocole 8 bits
Données variable
Version (4 bits) — 4 pour IPv4, 6 pour IPv6. Permet au routeur de savoir quel format de paquet traiter.
IP Source (32 bits) — Adresse de l'expéditeur. Ne change jamais durant tout le trajet (contrairement à la MAC qui change à chaque saut).
IP Destination (32 bits) — Adresse du destinataire final. Chaque routeur consulte ce champ pour décider où envoyer le paquet.
TTL (Time To Live, 8 bits) — Compteur initialisé par l'émetteur (souvent 64 ou 128). Chaque routeur le décrémente de 1. Si TTL = 0, le paquet est détruit → empêche les boucles infinies. C'est aussi le mécanisme exploité par traceroute.
Protocole (8 bits) — Identifie le contenu encapsulé : 6 = TCP, 17 = UDP, 1 = ICMP.
Données (variable) — Segment TCP, datagramme UDP ou message ICMP encapsulé.
Note
IP est un protocole sans connexion et non fiable : il ne garantit ni l'arrivée, ni l'ordre des paquets. C'est TCP (couche 4) qui s'en charge.

Passerelle par défaut

Quand une machine veut joindre une destination :

  • Si elle est dans le même sous-réseau → envoi direct (via ARP + switch)
  • Si elle est dans un autre réseau → envoi au routeur local = la passerelle par défaut

Principe du routage statique

En routage statique, l'administrateur saisit manuellement chaque route dans le routeur. Le routeur suit ces instructions à la lettre :

  1. Il lit l'IP de destination du paquet
  2. Il consulte sa table de routage
  3. Il choisit la route la plus précise (longest prefix match)
  4. Il transmet le paquet au prochain saut (next hop)

Limite du routage statique
Si le lien R1 → R3 tombe, la route par défaut pointe toujours vers R3 → les paquets sont perdus. L'admin doit intervenir manuellement. Le routage dynamique résout ce problème.

Pourquoi le routage dynamique ?

En routage statique, si un lien tombe, la route reste → les paquets sont perdus. En routage dynamique, les routeurs échangent automatiquement leurs routes et recalculent le meilleur chemin en cas de panne.

Routage statiqueRoutage dynamique
ConfigurationManuelle par l'adminAutomatique entre routeurs
AdaptationAucune — panne = perteRecalcul automatique
UsagePetits réseaux, route par défautEntreprises, opérateurs

RIP — Vecteur de distance

RIP (Routing Information Protocol) est le plus simple. Chaque routeur partage sa table de routage avec ses voisins directs. La métrique est le nombre de sauts (max 15).

OSPF — État de lien (détail)

OSPF (Open Shortest Path First) est le protocole de routage dynamique le plus utilisé en entreprise. Contrairement à RIP, chaque routeur connaît la topologie complète du réseau et calcule le plus court chemin avec l'algorithme de Dijkstra.

Fonctionnement d'OSPF

  1. Découverte — Les routeurs envoient des Hello pour découvrir leurs voisins
  2. Échange — Chaque routeur décrit ses liens (LSA — Link State Advertisement) et les diffuse
  3. Base de données — Tous les routeurs construisent la même LSDB (Link State Database) = carte complète
  4. Calcul — Chaque routeur exécute Dijkstra pour trouver le plus court chemin vers chaque destination
  5. Convergence — Si un lien change, un nouveau LSA est diffusé → recalcul automatique

Schéma interactif — OSPF et coûts des liens

OSPF utilise le coût (inversement proportionnel au débit) au lieu du nombre de sauts. Cliquez pour voir le chemin choisi :

OSPF calcule le coût total de chaque chemin. Le chemin via les liens 10 Gbit/s (coût 1+1=2) est préféré aux liens 100 Mbit/s (coût 10+10=20).
Calcul du coût OSPF
Le coût d'un lien OSPF est calculé par : coût = bande passante de référence / débit du lien.
Référence par défaut = 100 Mbit/s. Donc : lien 100 Mbit/s = coût 1, lien 10 Mbit/s = coût 10, lien 1 Gbit/s = coût 0.1 (arrondi à 1). On peut ajuster la référence pour les liens très rapides.

Les zones OSPF (Areas)

Dans un grand réseau, OSPF divise la topologie en zones pour limiter la taille de la LSDB :

  • Area 0 (backbone) — zone centrale, toutes les autres zones doivent y être connectées
  • Areas 1, 2… — zones périphériques contenant les réseaux locaux
  • Les ABR (Area Border Routers) font le lien entre zones

BGP — Le routage d'Internet

BGP (Border Gateway Protocol) est le protocole qui fait fonctionner Internet. Il échange des routes entre systèmes autonomes (AS) — les réseaux des opérateurs, hébergeurs, entreprises.

En résumé
RIP = simple, compte les sauts, limité à 15. Pour les très petits réseaux.
OSPF = intelligent, calcule le meilleur chemin selon le débit. Standard en entreprise.
BGP = le "GPS d'Internet", route entre opérateurs. Chaque opérateur est un AS.

ICMP — protocole de diagnostic

ICMP (Internet Control Message Protocol) ne transporte pas de données utilisateur. Il sert à envoyer des messages de contrôle, de diagnostic ou d'erreur.

Ping

Teste la joignabilité d'un équipement et mesure le temps de réponse (RTT) :

ping 8.8.8.8
ping google.com
Comment ça marche
ping envoie un message ICMP Echo Request. Si la cible est joignable, elle répond avec un Echo Reply. Le temps aller-retour (RTT) est mesuré pour chaque paquet.

Traceroute

Affiche les routeurs traversés jusqu'à la destination. L'outil exploite le TTL :

  1. Envoie un paquet avec TTL = 1 → le 1er routeur le détruit et renvoie un message ICMP "TTL exceeded"
  2. Envoie avec TTL = 2 → le 2e routeur répond
  3. Ainsi de suite jusqu'à la destination
traceroute google.com   # Linux / macOS
tracert google.com      # Windows

IPv6 — L'évolution d'IPv4

IPv4 est limité à ~4,3 milliards d'adresses. Avec l'explosion des objets connectés, c'est insuffisant. IPv6 utilise 128 bits → un espace d'adressage quasi-infini.

SLAAC — Auto-configuration sans serveur

SLAAC (Stateless Address Autoconfiguration) permet à une machine de se configurer toute seule en IPv6 :

  1. La machine génère une adresse link-local (fe80::...) à partir de sa MAC
  2. Elle envoie un Router Solicitation (multicast)
  3. Le routeur répond avec un Router Advertisement contenant le préfixe réseau
  4. La machine combine préfixe + identifiant = adresse globale complète
Pas de DHCP nécessaire en IPv6 !
SLAAC supprime le besoin d'un serveur DHCP pour l'attribution d'adresses. Cependant, DHCPv6 existe toujours pour fournir des infos complémentaires (DNS, nom de domaine…). En pratique, beaucoup de réseaux utilisent SLAAC + DHCPv6 en complément.
En pratique
IPv6 est activé par défaut sur tous les OS modernes (Windows, Linux, macOS). Votre machine a déjà une adresse IPv6 link-local ! Vérifiez avec ipconfig (Windows) ou ip -6 addr (Linux).
